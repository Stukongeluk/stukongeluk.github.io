Autonomous Ops: Hermes Agent on Synology NAS

How I containerized Hermes Agent in Docker on my Synology NAS, leveraging free models on OpenRouter, to run two daily automated operations: scanning freelance contracts with CV match scoring, and generating daily CBR driving theory questions for CapyDrive straight into Discord.

The Engineering Mindset: Automate Daily Toil

As a Senior DevOps and Full-Stack engineer, repetitive manual routines are candidates for automation. Two tasks were consuming unnecessary headspace every single day:

  1. Freelance Market Vigilance: Sifting through Freelance.nl, LinkedIn, and contractor boards every morning, filtering out low-ball rates and irrelevant keywords.
  2. CapyDrive Content Velocity: Generating authentic, high-quality Dutch driving theory (CBR) practice questions with fresh scenarios, distractors, and legal explanations.

Instead of manually checking websites or drafting questions over coffee, I deployed Hermes Agent inside a Docker container on my 24/7 Synology NAS. Every morning, it executes both tasks autonomously and dispatches formatted briefings directly to dedicated channels in my private Discord server.

The Setup: Synology NAS + Multi-Model Flexibility

The infrastructure is intentionally lightweight and cost-efficient:

  • Synology DSM Container Manager: Runs the Hermes Agent container with persistent volume mounts on the local Btrfs storage pool. The container sits at <200MB RAM with 0% idle CPU.
  • Multi-Model Flexibility with Zero GPU Tax: Rather than forcing heavy local LLM inference onto the NAS CPU (which leads to 1–3 tokens/sec and thermal throttling), Hermes Agent is inherently multi-model. It offloads reasoning to free models available on OpenRouter, giving the flexibility to select and switch between different models for scraping, reasoning, and synthesis with zero local hardware tax and zero API fees.
  • Discord Webhooks & Bot API: Serves as the universal notification interface. Discord mobile and desktop apps deliver push notifications with rich embeds, eliminating the need to build a custom frontend.

Why Hermes Agent Beats Frameworks Like OpenClaw

When evaluating open-source autonomous runtimes, OpenClaw (formerly Clawdbot/Moltbot) and NousResearch's Hermes Agent are the primary choices. For multi-task autonomous pipelines, Hermes Agent is demonstrably superior:

1. Closed Learning Loop vs. Static Message Relaying

OpenClaw functions primarily as a chat bridge connecting messaging apps to an LLM, relying on static vector memory plugins. In contrast, Hermes Agent implements a closed self-improving learning loop: it authors, evaluates, and refines its own Python tools and skills based on execution feedback. When a job board layout shifts or a question format needs adjusting, Hermes refines its internal tool logic rather than failing.

2. Native Structured Function Calling (<tool_call>)

NousResearch models are trained explicitly on the native <tool_call> function calling standard. When validating complex JSON schemas (contract rates, CBR multiple-choice answer keys, Discord webhook payloads), Hermes produces strictly compliant payloads. OpenClaw frequently suffers from schema drift and broken parameters.

3. Unattended Cron Pipelines

OpenClaw is designed around conversational turn-taking ("chatting with a bot"). Hermes Agent is architected for autonomous background jobs: triggering via schedule, executing multi-step search and generation workflows, and formatting Discord embeds without requiring human initiation.

Pipeline 2: CapyDrive Daily Exam Content Generator

In my CapyDrive case study, I shared that 70% of building a theory platform is ongoing content creation and SEO. Creating original CBR questions by hand is time-consuming.

Hermes Agent automates this creative bottleneck:

  • Rotating CBR Syllabus Topics: Every morning, the agent cycles through core CBR categories: Voorrang (Right of Way), Verkeersborden (Traffic Signs), Gevaarherkenning (Hazard Perception), and Milieu & Techniek.
  • CBR Exam Authenticity: Uses free models via OpenRouter to generate tricky edge-case traffic scenarios, plausible distractor options, and official explanations citing Dutch traffic legislation (RVV 1990).
  • 1-Click Review in Discord: Delivers the question into #capydrive-content with multiple-choice buttons or approval reactions for instant sync into CapyDrive's Firebase Firestore database.

Docker Setup & Synology Configuration

For the container installation itself, refer to the official Hermes Agent Docker documentation. On Synology Container Manager, the setup centers around a few key environment variables and a persistent storage mount:

  • Discord BOT Token: Configured via environment variables (such as DISCORD_BOT_TOKEN) so Hermes authenticates directly as a standalone bot in your Discord server.
  • Always-On Dashboard: Set DASHBOARD=1 so the agent boots with its native web dashboard enabled, making it easy to monitor active skills, logs, and task queues from any browser on the LAN.
  • Free OpenRouter Endpoints: Configured API credentials to query free models on OpenRouter, taking advantage of Hermes's multi-model flexibility without local GPU compute.
  • Persistent NAS Volume Mount: Mapped a persistent volume on the Synology storage pool (e.g. /volume1/docker/hermes/data) so skills, scraped cache, and conversation context are safely preserved across container updates and NAS reboots.

This makes lifecycle management on DSM effortless: when a new Hermes image is published, the container can simply be updated and restarted without losing any accumulated skills or historical data.

Security & Sandboxing: Why Docker on Synology is Crucial

Allowing an autonomous agent to scrape external job portals, parse third-party web content, and execute Python tool chains requires a strict security perimeter. Running Hermes Agent containerized in Docker provides essential defense-in-depth layers:

🛡️ Filesystem Sandboxing

The container is strictly constrained to its mounted volume (/app/data). It has zero read or write access to the Synology DSM root OS, system configurations, or private family and backup shares across the NAS storage pool.

🌐 Bridge Network Isolation

Sandboxed on an isolated Docker bridge network. The agent can only reach external APIs (OpenRouter, Discord) and cannot probe internal NAS administrative management ports (DSM 5000/5001) or other private LAN subnets.

🔒 Least-Privilege Execution

Runs as a dedicated non-root container user with dropped Linux capabilities and disabled root escalation, preventing privilege breakout from untrusted scraped HTML.

⚙️ Resource Quotas & DoS Guard

Hard memory and CPU limits ensure that even if a recursive scraping loop occurs, it cannot starve vital NAS workloads like automated RAID scrubbing, Time Machine backups, or media streaming.
